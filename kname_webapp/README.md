# K-Name Generator — 웹앱

카드(kname_card_flip_3) 디자인 그대로, 변환 이유까지 한 페이지에.

## 미리보기 (서버 없이)

`standalone/` 폴더의 파일을 더블클릭하면 바로 열립니다.
CSS·폰트가 파일 안에 들어 있어 외부 파일이 필요 없습니다.

| 파일 | 내용 |
|---|---|
| `input.html` | 입력 페이지 — 예시 3개는 클릭하면 결과 페이지로 이동 |
| `r_sophia.html` | Sophia Hernandez (Feminine) → 이수아 |
| `r_noah.html` | Noah Wilson (Masculine) → 이노을 |
| `r_byron.html` | Byron Smith (Either) → 서바다 (공용 이름) |

> `templates/index.html`은 Flask용 Jinja 템플릿이라 직접 열면
> `{% raw %}{% if %}{% endraw %}` 같은 문법이 그대로 보입니다. 미리보기는 `standalone/`을 사용하세요.

## 실행

```bash
# 1. 패키지 설치
pip install flask pandas openpyxl anthropic

# 2. API 키 설정 (사전 밖 이름 처리용)
export ANTHROPIC_API_KEY=sk-ant-...

# 3. 연결 확인 — 음차 품질까지 함께 점검
python check_llm.py

# 4. 실행
python app.py
```
→ http://localhost:5000

키가 없어도 실행은 됩니다. 다만 사전에 있는 이름(1,978개)만 변환되고,
그 밖의 이름은 안내 메시지가 나갑니다.

### check_llm.py가 확인하는 것
1. anthropic 패키지 설치 여부
2. API 키 설정 여부
3. 실제 호출 성공 여부
4. **음차 품질** — 사전의 정답과 대조 (Nguyen→응우옌 등 5건)
5. 사전 밖 이름 음차 결과
6. 의미 생성 동작

음차가 정답과 다르면 `lib/transliterate.py`의 `_GUIDE`에 예시를 추가하면 됩니다.

## 공유

`navigator.share` — 모바일에서 **네이티브 공유 시트**를 띄웁니다.
인스타그램·카카오톡·메시지·에어드롭 등 기기에 설치된 앱이 그대로 나타납니다.

| 환경 | 버튼 | 동작 |
|---|---|---|
| iOS · Android | `Share` | 공유 시트 (저장도 시트 안에 포함) |
| 데스크톱 | `Save image` | PNG 다운로드 |

환경을 감지해 버튼 라벨과 개수를 자동으로 바꾸므로, 중복 버튼이 보이지 않습니다.
공유 텍스트에는 이름과 사이트 주소가 함께 들어갑니다:
`Lee Su-a (이수아) — my Korean name / Get yours at mykoreanname.cc`

## 발음 듣기 (TTS)

**풀네임을 통째로 합성**하고 파일로 캐시합니다.

```
① static/audio/full/이수아.mp3   요청 시 생성 → 이후 재사용
② speechSynthesis               생성 실패 시 브라우저 내장 음성
```

### 왜 통째로 만드나
성씨와 이름을 따로 만들어 이어 붙이면 두 가지 문제가 생깁니다.
- 성씨 133 × 이름 602 = 8만 조합이라 미리 만들 수 없음
- 한 글자 성씨(`이`, `김` 등 126개)는 Chirp 3: HD가 **무음으로 합성**함

`이수아`처럼 3글자 이상이면 Chirp 3도 정상 처리하고, 목소리도 하나로 통일됩니다.

### 준비
```bash
pip install google-cloud-texttospeech
export GOOGLE_APPLICATION_CREDENTIALS=gcp-key.json
```
Google Cloud 콘솔에서 Cloud Text-to-Speech API를 켜고 서비스 계정 키(JSON)를 발급하세요.

키가 없어도 앱은 동작합니다 — 브라우저 내장 음성으로 폴백합니다.

### 음성 변경
`lib/tts_full.py` 상단에서 바꿉니다.

```python
DEFAULT_VOICE = 'ko-KR-Neural2-A'   # 여성. 남성은 ko-KR-Neural2-C
SPEAKING_RATE = 0.70                # 낮을수록 느림
PITCH = 0.0                         # 음높이 변화
```

**Chirp 3: HD를 기본으로 쓰지 않는 이유**
표현력이 좋은 대신 이름 하나를 읽을 때 억양이 과하게 실리고,
`speaking_rate` 를 지원하지 않아 속도 조절이 되지 않습니다.
이름을 또박또박 들려주는 용도에는 억양이 평이한 Neural2가 적합합니다.

억양을 더 줄이려면 `ko-KR-Standard-A` 도 선택지입니다(기계적이지만 단조로움).

### 음성 비교
여러 음성·속도를 같은 이름으로 만들어 나란히 들어볼 수 있습니다.

```bash
python compare_voices.py                 # 후보 6종 · 이수아 · 0.70
python compare_voices.py --text 이노을
python compare_voices.py --rate 0.6 0.7 0.85
python compare_voices.py --all           # 계정의 한국어 음성 전부
```

결과는 `static/audio/_compare/` 에 `음성이름__속도.mp3` 형식으로 저장됩니다.
속도를 지원하지 않는 음성은 파일명에 `rate없음` 으로 표시됩니다.

### 비용
이름 하나가 3글자 남짓이라 월 10만 명이 써도 무료 한도(100만 자) 안입니다.
한 번 만든 이름은 캐시되어 다시 호출되지 않습니다.

### 진단
`http://localhost:5000/diag` 에서 인증 상태·캐시 개수·재생 테스트를 할 수 있습니다.


## 카드 기능
- **탭하면 뒤집기** — 앞면(이름·한자·의미) / 뒷면(성씨 유래 + 이름 의미)
- **Share to Story** — 모바일 공유 시트, 미지원 시 자동 저장
- **Save image** — 2× 레티나 PNG (616×1096) 다운로드
- **Hear pronunciation** — 한국어 TTS(ko-KR)로 이름 읽어줌

## 폰트 주의사항
업로드하신 카드에는 3개 폰트가 base64로 임베드돼 있었어요.
- `EngSerif` — 라틴 전체 커버 → **그대로 사용** (static/fonts.css, 59KB)
- `KRDisplay` / `HanjaSerif` — **'이수아/李秀雅' 3글자만 포함된 서브셋**
  → 이름이 매번 바뀌는 웹앱에선 다른 글자가 안 나오므로 제외,
    한글·한자는 시스템 세리프(Noto Serif KR 등)로 폴백

전체 한글/한자 웹폰트를 쓰고 싶으면 서브셋이 아닌 정식 폰트를 static/에 넣고
style.css의 `--kr`, `--hanja` 변수만 바꾸면 돼요.

## 배포 시 확인사항

### 환경변수

| 변수 | 필수 | 설명 |
|---|:---:|---|
| `ANTHROPIC_API_KEY` | 권장 | 없으면 사전 안 이름만 변환 |
| `GOOGLE_APPLICATION_CREDENTIALS` | 선택 | 없으면 브라우저 내장 음성 사용 |
| `CACHE_DIR` | **권장** | 영속 디스크 경로. 아래 참고 |
| `PORT` | 자동 | 대부분의 PaaS가 자동 주입 |
| `FLASK_DEBUG` | ✗ | **운영에서 절대 켜지 마세요** |

### 캐시 영속화가 중요한 이유

캐시가 재시작 때 사라지면 같은 이름을 계속 다시 호출해 **비용이 선형 증가**합니다.
Render 무료 플랜처럼 파일시스템이 임시인 환경에서는 영속 디스크를 붙이고
`CACHE_DIR` 로 지정하세요.

```
CACHE_DIR=/var/data      # 예: Render Persistent Disk
```

캐시가 유지되면 흔한 이름부터 소진되어 API 호출이 빠르게 줄어듭니다.

### 타임아웃

응답이 없을 때 사용자가 무한정 기다리지 않도록 제한을 두었습니다.

| 호출 | 타임아웃 | 재시도 |
|---|---|---|
| 음차 · 의미 (Anthropic) | 20초 | 3회 |
| 음성 (Google TTS) | 8초 | — |

### TTS는 페이지 렌더링과 분리

음성 생성은 `/api/tts` 로 따로 요청합니다.
카드·의미·변환이유는 즉시 표시되고(평균 80ms), 음성은 재생 버튼을 눌렀을 때 만들어집니다.
생성에 실패해도 브라우저 내장 음성으로 대체됩니다.

### API가 모두 죽어도

변환·변환이유는 로컬 계산이라 영향이 없고, 사전 안 이름(1,978개)은 정상 동작합니다.
사전 밖 이름만 안내 메시지가 나갑니다. **사이트가 멈추지 않습니다.**

## API 비용

과금되는 곳은 **LLM 호출 2곳뿐**입니다. 변환·변환이유·TTS는 전부 로컬 계산이라 비용이 없습니다.

| 단계 | 모듈 | 언제 | 1건 비용 |
|---|---|---|---|
| 음차 | `transliterate.py` | 사전(2,278개)에 없는 이름 | 약 1.6원 |
| 의미 설명 | `meaning_en.py` | 602개 밖 이름 | 약 3.8원 |

**신규 이름 1건당 약 7원.** 사전에 있는 흔한 이름은 0원이고,
한 번 호출한 이름은 캐시에 저장되어 재과금되지 않습니다.

### meaning_en.py — 영어 전용 생성기
`meaning.py`는 한국어와 영어를 함께 만들지만 이 앱은 영어만 사용합니다.
버려지는 한국어 출력과 장황한 예시 프롬프트를 걷어내 비용을 낮췄습니다.

```
meaning.py     프롬프트 2,156자 + 출력 400토큰 → 10.7원
meaning_en.py  프롬프트   595자 + 출력 150토큰 →  3.8원  (65% 절감)
```

생성에 실패하면 `meaning.py`로 폴백하고, 그마저 실패하면
번역표로 영어 문장을 조립하므로 한국어가 노출되지 않습니다.

### 오류 처리

API 오류는 성격이 다르므로 다르게 다룹니다.

| 유형 | 예 | 대응 |
|---|---|---|
| `transient` | 529 과부하 · 429 레이트리밋 · 5xx · 타임아웃 | SDK가 지수 백오프로 4회 재시도 |
| `credit` | 크레딧 소진 | 재시도해도 안 되므로 안내만 |
| `auth` | 키 오류 | 〃 |

**재시도로도 실패하면 저품질 문구를 만들지 않습니다.**
모든 이름에 똑같이 적용되는 일반 문장은 서비스가 성의 없어 보이게 만들기 때문에,
대신 상태를 알리고 재시도 버튼을 제공합니다.

```
이름 · 한자 · 발음 · 변환이유 → 계산이라 항상 정상 표시
의미 설명                     → 실패 시 "요청이 많아 잠시 지연" + Try again
```

Reddit 유입처럼 트래픽이 급증하면 429가 뜰 수 있습니다.
`translit_cache.json`이 살아 있으면 반복 요청은 API를 타지 않으므로
캐시 영속화가 곧 오류 예방입니다.

### 캐시 (배포 시 주의)
- `translit_cache.json` · `meaning_en_cache.json`
- 서버 재시작 시 사라지는 환경(예: Render 무료 플랜)에서는
  같은 이름을 계속 재호출하므로 **영속 디스크에 두어야** 합니다.

## 음차 (영어 → 한글)

`lib/transliterate.py` — 이름·성씨 공통. `meaning.py`와 같은 2단계 구조.

```
Kowalski
  ↓
① 사전 조회   dict_name_to_translit.json (이름 1,978 / 성씨 300)   ← 무료·즉시
  ↓ 없으면
② 캐시 조회   translit_cache.json                                  ← 재호출 방지
  ↓ 없으면
③ LLM 생성    Claude 호출 → '코왈스키' → 캐시에 저장                ← ANTHROPIC_API_KEY 필요
  ↓
엔진이 '코왈스키' → 한국 성씨 '고(高)' 매칭
  ↓
SURNAME_INFO에서 한자·순위·유래설명 조회 (한국 성씨 29개 전부 보유)
```

음차가 실패하면 **규칙 기반으로 추측하지 않고 None을 반환**합니다.
음차 정확도가 결과 전체의 품질을 좌우하므로, 어설픈 추측보다 안내 메시지가 낫습니다.

### 음차 오류 최소화

LLM은 철자를 영어식으로 읽어 틀리는 경우가 있습니다
(Fionn → 피온, Takumi → 타쿠미, Iker → 아이커). 세 겹으로 대응합니다.

**① 사전 선반영 — 가장 확실**
발음이 까다로워 자주 틀리는 이름 170개를 사전에 직접 넣었습니다.
사전에 있으면 LLM을 아예 호출하지 않으므로 오류 가능성이 0입니다.

```
아일랜드  Fionn 핀 · Aisling 애슐링 · Saoirse 서샤 · Caoimhe 키바
일본      Takumi 다쿠미 · Kenjiro 겐지로   (어두 t·k는 평음)
바스크    Iker 이케르 · Etxeberria 에체베리아
중국      Xiaoli 샤오리 · Ouyang 어우양
네덜란드  Sanne 산네 · Anneke 안네커      (어말 -e 발음)
```

**② 프롬프트에 언어별 규칙 명시**
어원을 먼저 판별하고 그 언어의 발음으로 옮기도록 단계를 나눴고,
자주 틀리는 언어권(아일랜드·일본·바스크·중국·네덜란드·프랑스·슬라브·아프리카)의
규칙과 예시를 넣었습니다.

**③ 출력 검증**
- 경음(쓰·쯔·뻐 등)이 나오면 폐기 — 외래어 표기법에서 쓰지 않음
- 원래 철자 대비 음절 수가 터무니없으면 1회 재시도

### 왜 LLM인가
철자만으로는 원어 발음을 알 수 없어 규칙 기반으로는 한계가 뚜렷합니다.
`Nguyen → 응우옌`(베트남어), `Sean → 숀`·`Siobhan → 시본`(아일랜드어),
`Xavier → 제이비어`처럼 어원별 발음을 반영해야 하기 때문입니다.

### 사전 밖 이름의 부가정보
- 성씨: `SURNAME_INFO` (한국 성씨 29개) — 엔진이 매칭한 성씨로 역조회
- 이름: `GIVEN_INFO` (620개) — 변환된 한국이름으로 역조회

한국 성씨는 29개, 이름은 602개로 유한하므로 **음차만 되면 그 뒤 단계는 항상 채워집니다.**

## 입력 페이지

`templates/index.html` — 카드와 같은 톤(아이보리 배경 · EngSerif · 안쪽 테두리)

- **First name** 직접 입력 (필수)
- **Last name** 직접 입력 (필수 — 한국 이름은 성+이름이 한 세트이고, 카드 뒷면의 성씨 유래 섹션도 성씨가 있어야 표시됨)
- **Name style** 3지선다: `Masculine` / `Feminine` / `Either`

### Either 선택 시 성별 표현

미리 작성된 602개 설명 중 **250개**가 `a boy's name`, `her grace` 같은
성별 표현을 담고 있습니다. 사용자가 Either 를 골랐는데 성별을 단정하면
선택이 무시된 셈이므로, 해당 표현을 중립으로 바꿉니다.

```
a boy's name        → a given name
boys'-name charts   → name charts
never loses her grace → never loses their grace
```

- 남/여를 고른 경우에는 원문을 그대로 둡니다.
- LLM이 새로 생성할 때도 성별을 명시하지 말라고 프롬프트에 지시합니다.
- `OH MY GIRL` 같은 그룹명은 고유명사로 보호해 바꾸지 않습니다.

검증: Either 120건에서 성별 표현 잔존 0건.

### Either(그 외) 처리 방식
엔진은 남/여만 받으므로 별도 로직으로 처리합니다 (`app.py::_pick_neutral`).

1. 남녀 사전을 **모두** 조회해 후보를 수집 (각 사전의 1·2순위 결과)
2. **남녀 공용으로 쓰이는 이름**이 있으면 우선 선택
3. 없으면 품질(Q1 > Q2 > Q3 > Q4)이 가장 좋은 결과

공용 이름은 18개이며 대부분 순우리말입니다 —
가람 · 노을 · 누리 · 라온 · 로하 · 루빈 · 루하 · 리안 · 리온 · 리우 ·
마음 · 바다 · 아민 · 예담 · 온유 · 지민 · 태림 · 태이

실제로 공용 이름이 나오는 비율은 약 8%이며(예: Byron→바다, Guadalupe→가람),
나머지는 품질이 가장 좋은 결과가 선택됩니다.
결과 데이터에 `is_unisex` 플래그가 포함돼 있어 필요하면 화면에 표시할 수 있습니다.

## 순우리말 이름

602개 중 14개는 한자 없이 쓰는 순우리말 이름입니다.

```
기쁨 다솜 미르 바다 봄이 빛나 예봄
이든 이봄 이플 하늘 하늬 한빛 힘찬
```

한자가 비어 있으면 누락으로 보이므로 두 곳에서 명시합니다.

**카드 앞면** — 한자 뜻 줄 자리에
`a native Korean name — written without hanja`

**변환 이유** — 별도 안내 상자(`cr-note-native`)
한국 이름이 한자어 이름과 순우리말 이름으로 나뉜다는 점,
그리고 순우리말 이름이 가진 어감(부드럽고 트인 소리, 한자의 격식이 없는 친근함,
듣는 즉시 뜻이 전해지는 명료함)을 설명합니다.

판단은 `d.is_native`(이름 한자 유무)로 하며, 성씨 한자는 그대로 표시됩니다.

## 음절 매칭 판정 기준 (음성학 자질 기반)

`lib/phonetics.py` — 한국어 음소를 조음 자질로 표현하고 자질 거리로 유사도를 계산.

**음절 유사도 = 초성 0.44 + 중성 0.40 + 종성 0.16**
(각 성분 유사도에 대비지수 2.5를 적용 — 자질이 여러 개면 하나만 달라도
 나머지가 점수를 떠받쳐 변별력이 떨어지므로 대비를 높임)

| 성분 | 자질 |
|---|---|
| 초성(자음) | 조음위치(양순~성문) · 조음방법(파열/비음/유음/마찰/파찰) · 발성유형(평음·격음·경음) |
| 중성(모음) | 혀높이 · 전후설 · 원순성 · 활음(y/w) |
| 종성(받침) | 7종 대표음으로 중화 후 자음 자질 비교 · 유무 차이는 0.55 |

| 점수 | 라벨 | 색 | 비중 |
|---|---|---|---|
| 0.87 이상 | strong | 진초록 `#1D9E75` | 60% |
| 0.68 이상 | partial | 연두 `#639922` | 20% |
| 0.52 이상 | soft | 황토 `#BA7517` | 15% |
| 0.52 미만 | loose | 적갈 `#D85A30` | 6% |

임계값은 실제 매칭 466건 분포로 보정했습니다.

**설계 근거**
- 영어 화자는 음절 첫 자음에 먼저 반응 → 초성 비중을 가장 높게
- 받침이 붙고 빠지는 것은 모음이 통째로 바뀌는 것보다 작은 변화
  → 이(I)→인(In) 0.88 > 소(So)→수(Su) 0.86
- ㄱ/ㄲ/ㅋ 같은 평음·경음·격음 구분은 영어 화자에게 거의 같은 소리 → 발성유형 비중 최소

**예시**

| 매칭 | 점수 | 판정 | 근거 |
|---|---:|---|---|
| 아→아 | 1.00 | strong | 완전 동일 |
| 데→대 | 0.93 | strong | 자음 ㄷ 동일, 모음 ㅔ/ㅐ 근접 |
| 이→인 | 0.88 | strong | 초·중성 동일, 받침만 추가 |
| 소→수 | 0.86 | partial | 자음 ㅅ 동일, 모음 ㅗ/ㅜ 후설 원순으로 근접하나 높이 다름 |
| 세→재 | 0.68 | soft | 모음 근접, 자음 ㅅ/ㅈ 조음위치만 유사 |
| 시→인 | 0.44 | loose | 모음만 같고 자음은 유/무로 갈림 |
